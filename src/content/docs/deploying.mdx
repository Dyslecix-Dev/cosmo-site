Cosmo builds to fully static HTML, CSS, and JS in `./dist/`. Any static host works. Four common options are documented below.

<Callout type="note">
Before deploying, set `site` in `astro.config.mjs` to the production URL you'll deploy to. The `SEO.astro` component throws at build time if it isn't set, and the sitemap and RSS feed both rely on it for absolute URLs.
</Callout>

<Callout type="note" title="Package manager">
Examples below use **pnpm**. The template also supports **npm** and **yarn** — substitute `npm install` / `npm run build` or `yarn install` / `yarn build`, and use the matching lockfile (`package-lock.json` or `yarn.lock`) for cache and install commands.
</Callout>

## Common build settings

Every host below uses the same build inputs:

- **Install command:** `pnpm install --frozen-lockfile` (or `npm ci` / `yarn install --frozen-lockfile`)
- **Build command:** `pnpm build` (or `npm run build` / `yarn build`)
- **Output directory:** `dist`
- **Node version:** `22 LTS` (matches `.nvmrc`)

## Cloudflare Pages

1. Push the repo to GitHub, GitLab, or Bitbucket.
2. In the Cloudflare dashboard, go to **Workers & Pages → Create → Pages → Connect to Git** and pick the repo.
3. In **Build settings**, set:
   - **Framework preset:** Astro
   - **Build command:** `pnpm build`
   - **Build output directory:** `dist`
4. Under **Environment variables (Build)**, add:
   - `NODE_VERSION` = `22`
5. Save and deploy. Cloudflare will rebuild on every push to the production branch.

To use a custom domain, add it under **Custom domains** and point your DNS at the provided CNAME (or use Cloudflare DNS for one-click setup).

## GitHub Pages

GitHub Pages serves static files from a branch or from a workflow artifact. Cosmo recommends the workflow approach — it lets the build run in CI rather than committing `dist/` to the repo.

1. In the repo settings, go to **Settings → Pages** and set **Source** to **GitHub Actions**.
2. Add a workflow at `.github/workflows/deploy.yml`:

   ```yaml
   name: Deploy to GitHub Pages

   on:
     push:
       branches: [main]
     workflow_dispatch:

   permissions:
     contents: read
     pages: write
     id-token: write

   concurrency:
     group: pages
     cancel-in-progress: true

   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: pnpm/action-setup@v4
         - uses: actions/setup-node@v4
           with:
             node-version: 22
             cache: pnpm
         - run: pnpm install --frozen-lockfile
         - run: pnpm build
         - uses: actions/upload-pages-artifact@v3
           with:
             path: dist
     deploy:
       needs: build
       runs-on: ubuntu-latest
       environment:
         name: github-pages
         url: ${{ steps.deployment.outputs.page_url }}
       steps:
         - id: deployment
           uses: actions/deploy-pages@v4
   ```

3. If you're deploying to a project page (`username.github.io/repo`), set `base: "/repo"` in `astro.config.mjs` so asset paths resolve correctly. User/org pages (`username.github.io`) don't need this.

<Callout type="danger">
GitHub Pages does not serve a `404.html` from arbitrary paths the way other hosts do. Astro's static `404.astro` is built to `dist/404.html` and Pages does serve it for unknown URLs — but only at the site root, not under custom 404s for subdirectories.
</Callout>

## Netlify

1. Push the repo to your Git provider.
2. In Netlify, go to **Add new site → Import an existing project** and pick the repo.
3. Set:
   - **Build command:** `pnpm build`
   - **Publish directory:** `dist`
4. Under **Site settings → Build & deploy → Environment**, add:
   - `NODE_VERSION` = `22`
   - `NPM_FLAGS` = `--version` *(only if using pnpm — disables Netlify's default `npm install` so it falls through to pnpm; skip this if you're already using npm or yarn)*
5. Optionally commit a `netlify.toml` to pin everything in the repo:

   ```toml
   [build]
   command = "pnpm build"
   publish = "dist"

   [build.environment]
   NODE_VERSION = "22"
   ```

Netlify auto-detects pnpm via `pnpm-lock.yaml` (or npm/yarn via their respective lockfiles) and installs the matching package manager for you.

## Vercel

1. Push the repo to your Git provider.
2. In Vercel, click **Add New → Project**, import the repo, and accept the auto-detected **Astro** preset.
3. Vercel reads your lockfile (`pnpm-lock.yaml`, `package-lock.json`, or `yarn.lock`) and uses the matching package manager automatically. Defaults work:
   - **Build command:** `pnpm build`
   - **Output directory:** `dist`
   - **Install command:** `pnpm install`
4. Under **Project Settings → General**, confirm **Node.js Version** is `22.x`.
5. Deploy. Every push to the production branch redeploys; PRs get preview URLs automatically.

## After your first deploy

- Verify the sitemap is reachable at `/sitemap-index.xml` and that `robots.txt` points to the production URL.
- Test the RSS feed at `/rss.xml`.
- Check that OG images render by pasting your URL into the [Open Graph debugger](https://www.opengraph.xyz/) or a Slack/Discord message.
- Run [PageSpeed Insights](https://pagespeed.web.dev/) against the deployed URL to confirm the build is performing as expected.
