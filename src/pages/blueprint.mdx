This site runs on the <a href="https://cosmo-example.dyslecix.dev/" target="_blank" rel="noopener noreferrer">Cosmo template</a>. The original purpose was to find any rough edges that needed to be smoothed out for the developer experience. If you're adapting Cosmo for a marketing or docs site, this is a real world look into how it works.

You can find the source code <a href="https://github.com/DyslecixDev/cosmo-site" target="_blank" rel="noopener noreferrer">here</a>.

## When Cosmo is the right pick

Cosmo was made for a wide range of static sites: portfolios, blogs, etc. If you need versioned docs, deep nav, built-in search, or i18n on day one, <a href="https://starlight.astro.build/" target="_blank" rel="noopener noreferrer">Starlight</a> gives you all of that out of the box. Cosmo trades those features for an agnostic codebase with minimal opinionated code.

## What we removed

- There's no blog on this site, so we pulled `src/content/blog/`, dropped the `blog` entry from `src/content.config.ts`, and removed the matching routes (`src/pages/blog/`, `src/pages/tags/`).
- The blog-specific layouts and partials that came with it.
- The example posts the template ships with.

## What we kept

- The Hero, Marquee, Features, and Charts sections under `src/components/sections/` are template-derived. All we did was style it.
- Another style refresh on the Navbar and Footer with the links now pointing at our docs and the GitHub repo.
- The theme system's design tokens in `src/styles/global.css`, plus the dark/light mode toggle and the motion preference toggle.
- The `astro-seo` wrapper at `src/components/SEO.astro`, with `siteName` and `titleDefault` swapped over.
- Astro fonts via the `astro:assets` Font component, which are wired up in `BaseLayout`.
- The reusable Callout component handles `note`, `tip`, `warning`, and `danger`.

## What we added

### A `docs` content collection

Defined in `src/content.config.ts` with a tight Zod schema (`title`, `description`, `order`, `updatedDate`, `draft`).

Two routes render it:
- `src/pages/docs/index.astro` — a themed card grid, sorted by `order`.
- `src/pages/docs/\[slug\].astro` — the detail page, with a table of contents, prev/next, an "edit on GitHub" link, and JSON-LD.

### Per-doc themed backgrounds

A small lookup at `src/lib/doc-themes.ts` maps each doc slug to a visual theme: Solar System, Pulsar, and so on. New docs without a registered theme fall back to the "Deep Space" nebula.

### Blueprint + roadmap + privacy + a custom 404

The page you're reading is itself an addition. `src/pages/blueprint.mdx` and `src/pages/roadmap.mdx` each get their own layout, `EventHorizonLayout.astro` and `PortholeLayout.astro`, so they can have a distinct visual identity from the rest of the site without bleeding into `BaseLayout`.

Additionally, there are two more top-level Astro pages at `src/pages/privacy.astro` and `src/pages/404.astro`.

### A weighted sitemap

`@astrojs/sitemap` is wired up in `astro.config.mjs` with custom `changefreq` and `priority` values. The 404 is excluded, and `/privacy` is deprioritized.

### JSON-LD schema

Two flavors:
- WebSite + Organization on the homepage.
- TechArticle + BreadcrumbList on each doc detail page.

Both are emitted as inline `<script type="application/ld+json">` in `BaseLayout.astro` and in `[slug].astro` respectively.

### Cookieless analytics

<a href="https://www.cloudflare.com/web-analytics/" target="_blank" rel="noopener noreferrer">Cloudflare Web Analytics</a> has no consent banner because there are no cookies nor session replay. DNS lives at Namecheap rather than going through Cloudflare's proxy, so the beacon is injected by hand in `BaseLayout.astro` instead of relying on auto-injection. The CSP allows `static.cloudflareinsights.com` in `script-src` and `cloudflareinsights.com` in `connect-src`.

### Security headers

Set in `public/\_headers`: CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`. The CSP allows `'unsafe-inline'` in `script-src` because Astro 6 inlines hoisted `<script>` tags by default. The XSS surface here is essentially zero since there is no user-rendered HTML.

<Callout type="warning" title="CSP control">
If your site renders any user-controlled HTML (comments, search-driven content, anything coming back from an API) don't copy this CSP as-is. Tighten `script-src` first. The reasoning above only holds because no untrusted input ever reaches the page.
</Callout>

### Theme + motion bootstrap, lifted into `public/theme.js`

A blocking script that runs before paint to set the initial theme and motion preference, so you don't get a flash of unstyled content. It lives outside the bundler so the document `<head>` can pull it in synchronously.

### Build-time GitHub stars badge

The Hero shows a live star count for the upstream Cosmo repo. Instead of pulling <a href="https://shields.io/" target="_blank" rel="noopener noreferrer">shields.io</a> at runtime (which would mean a third-party request on every page view, plus an extra `img-src` entry in the CSP), we hit the GitHub API once at build time and bake the number into the static output.

### Native CSS view transitions

Page navigations use the browser's <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_view_transitions" target="_blank" rel="noopener noreferrer">CSS View Transitions API</a> via `@view-transition { navigation: auto; }` in `src/styles/global.css` instead of `<ClientRouter />`. Each navigation is still a full document load, but the browser cross-fades the old and new pages with a "warp" keyframe on `::view-transition-old(root)` and `::view-transition-new(root)`. The fixed `.porthole-scene` and `.horizon-scene` backdrops are hidden during `html:active-view-transition` so Safari doesn't bail out trying to snapshot them, and the whole effect is gated behind `prefers-reduced-motion`.

### Google Search Console verification

Added as a `<meta name="google-site-verification">` tag in `BaseLayout.astro`. We went with the HTML tag method instead of DNS so verification stays next to the site config.

## Recipes we used

This site is mostly Cosmo in its plainest form. The few "recipes" we leaned on are documented separately:

- [Rebranding theme](/docs/rebranding-theme) — we tweaked the design tokens but left the structure alone.
- [Managing content collections](/docs/managing-content-collections) — the `docs` collection follows that guide directly.
- [SEO checklist](/docs/seo-checklist) — we ran through it end-to-end before launch.
- [Deployment](/docs/deployment#cloudflare-pages) — this site is deployed via Cloudflare Pages.
