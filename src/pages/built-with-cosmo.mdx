This site (`cosmo.dyslecix.dev`) is scaffolded from the [Cosmo template](https://cosmo-example.dyslecix.dev/) — dogfooding it in production. This page is the **diff against the template**: what was kept, what was deleted, and what was added. Use it as a reference when adapting Cosmo for your own marketing or docs sites.

The full source lives at [DyslecixDev/cosmo-site](https://github.com/DyslecixDev/cosmo-site).

## When to reach for Cosmo

Cosmo is a good fit when you want a **lighter docs site sitting next to a marketing landing page** — one or two dozen guides, a collection of blogs, or a hand-tuned portfolio. If you need versioned docs, deep nav, built-in search, or i18n out of the box, [Starlight](https://starlight.astro.build/) is the batteries-included option for docs. Cosmo trades those features for full design control.

## What was deleted

- The `blog` content collection — this site has no blog. Deleted `src/content/blog/`, removed the `blog` definition from `src/content.config.ts`, and dropped the blog-related routes (`src/pages/blog/`, `src/pages/tags/`).
- The blog-specific layouts and partials.
- Seed content (the example posts that ship with the template).

## What was kept

- The whole **landing page architecture**: the Hero, Marquee, Features, and Charts sections under `src/components/sections/` are all template-derived. The marquee and chart variants were rewritten to market the template itself.
- **Navbar / Footer** structure, with content swapped to point at docs and the GitHub repo.
- **Theme system** — design tokens in `src/styles/global.css` under `@theme`, plus the dark/light toggle and motion-preference toggle.
- **`astro-seo` wrapper** at `src/components/SEO.astro`, with `siteName` and `titleDefault` adjusted.
- **Astro fonts** via the `astro:assets` Font component, wired in `BaseLayout`.

## What was added

### A `docs` content collection

Defined in `src/content.config.ts` with a tight Zod schema (`title`, `description`, `order`, `updatedDate`, `draft`). Files live under `src/content/docs/`.

Two routes render the collection:
- `src/pages/docs/index.astro` — themed card grid, sorted by `order`.
- `src/pages/docs/\[slug\].astro` — detail page with table of contents, prev/next, "edit on GitHub", and JSON-LD.

### Per-doc themed backgrounds

A small lookup of `src/lib/doc-themes.ts` maps each doc slug to a visual theme (Solar System, Pulsar, Wormhole, etc). The theme drives the card preview on the docs index and the gradient backdrop on the detail page. New docs without a registered theme fall back to the "Deep Space" nebula.

### MDX callouts

A single Callout component covers `note`, `tip`, `warning`, and `danger`. Imported in `.mdx` files when needed.

### Privacy + custom 404

Top-level Astro pages at `src/pages/privacy.astro` and `src/pages/404.astro`.

### Sitemap with per-page weights

`@astrojs/sitemap` is wired in `astro.config.mjs` with custom `changefreq` / `priority`, the 404 excluded, and `/privacy` deprioritized.

### JSON-LD schema

Two flavors:
- **WebSite + Organization** on the homepage.
- **TechArticle + BreadcrumbList** on each doc detail page.

Emitted as inline `<script type="application/ld+json">` in `BaseLayout.astro` and `[slug].astro`.

### Cookieless analytics

[Cloudflare Web Analytics](https://www.cloudflare.com/web-analytics/) — no consent banner, no cookies, no session replay. Because DNS is on Namecheap (not proxied through Cloudflare), the beacon is **injected manually** in `BaseLayout.astro` rather than via auto-injection. The CSP `script-src` allows `static.cloudflareinsights.com` and `connect-src` allows `cloudflareinsights.com`.

### Security headers

Set in `public/\_headers`: CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. The CSP allows `'unsafe-inline'` in `script-src` because Astro 6 inlines hoisted `<script>` tags by default. The XSS surface here is near-zero (static marketing/docs and no user-rendered HTML), so the pragmatic call won out over a hash-based CSP that would need hash management or an integration like [astro-shield](https://github.com/kindspells/astro-shield).

<Callout type="warning">
If your site renders any user-controlled HTML (comments, search-driven content, anything from an API), do **not** copy this CSP verbatim — tighten `script-src` first. The justification here is "no untrusted input ever reaches the page."
</Callout>

### Theme + motion bootstrap extracted to `public/theme.js`

A blocking script that runs before paint to set the initial theme and motion preference, preventing flash of unstyled content. Lives outside the bundler so it's loaded synchronously from the document `<head>`.

### Google Search Console verification

Added as a `<meta name="google-site-verification">` tag in `BaseLayout.astro`. Verified via the HTML tag method rather than DNS to keep verification co-located with the site config.
