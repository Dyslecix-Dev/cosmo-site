Cosmo's roadmap is organized around one rule: **guides drive recipes**. Use-case guides come first and optional-integration recipes are written when a guide pulls them in, when someone files an [issue](https://github.com/DyslecixDev/cosmo/issues) asking for one, or when a real project reaches for one.

## In progress: use-case guides

Each guide turns Cosmo into a specific kind of site. The output of each is: a public example repo (named `cosmo-<usecase>`), a deployed live demo, and a writeup whose spine is the **diff against Cosmo** — files added, modified, deleted.

- **Docs site + landing page** — already shipped (this site). A short ["Built with Cosmo"](/built-with-cosmo) writeup documents the diff.
- **Blog** — an upcoming philosophy blog.
- **Portfolio** — my own personal web dev portfolio.
- **Storefront** — a faux e-commerce site.

## Next: optional integration recipes

Short copy-paste guides for optional integrations. Recipes are written when one of the use-case guides above pulls them in or when a user requests one. The current candidate list spans framework integrations, UI libraries, code blocks, CMS options, search, state, comments, forms, email, payments, images, performance, testing, deployment, analytics, monitoring, and accessibility tooling.

If you would use Cosmo for a specific recipe, that's the most useful kind of issue to file — it's the demand signal that moves options from "candidate" to "queued." 

[Open a recipe request &rarr;](https://github.com/DyslecixDev/cosmo/issues/new/choose)
